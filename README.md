# YoSOM — Vendor Intelligence for Yale SOM Dining

A two-sided AI system that turns student food input into operating decisions for Yale School of Management's dining venues — **Charley's Place** and **McNay Cafe**.

🔗 **Live demo**

- **Student app** (mobile, chat-style): [yosom.vercel.app](https://yosom.vercel.app)
- **Vendor console** (desktop dashboard): [yosom.vercel.app/manager](https://yosom.vercel.app/manager)

---

## What it does

Students open a chatbot via QR code, share preferences in 60 seconds, vote on candidate menu items, and add free-text cravings. Every interaction writes to MongoDB.

On the other side, venue managers open a desktop console that turns those signals into action:

- **Overview dashboard** — KPIs, satisfaction pulse, top voted items, dietary breakdown, word cloud of student voice.
- **3-input demand forecast** — predicted servings for next week, computed from survey signal × campus events × exchange weeks.
- **AI Ops Brief** — daily brief generated by Claude: what to add, keep, or drop on next week's menu, budget impact, dietary flags, top student quotes.
- **Raw data** — filterable tables of every vote, reaction, preference, and chat transcript.
- **Posters studio** — DALL-E-generated promotional posters for next-week menu features, ready to push back into the student app.

## How generative AI is used

| Where | Model | Role |
|---|---|---|
| Student chat | Claude Haiku 4.5 | Conversational glue, off-topic classification, post-session tag extraction |
| Vendor ops brief | Claude Haiku 4.5 | Synthesize aggregated signals + cost table + forecast into a structured JSON brief |
| Promo posters | OpenAI DALL-E 3 | Generate print- and social-ready posters from item + vibe + aspect inputs |

The brief generator uses a multi-step flow: aggregate Mongo collections deterministically, compute scoring and forecast in TypeScript, hand a payload to Claude with a strict JSON schema, then reconcile Claude's output against the cost table to prevent hallucinated numbers from reaching the manager.

Next.js 14 (App Router) · TypeScript · MongoDB Atlas + Mongoose · Tailwind CSS · Recharts · Anthropic SDK · OpenAI SDK · Vercel

## Run locally

```bash
git clone https://github.com/Hugo1223gogo/YoSOM-vendor-intelligence.git
cd YoSOM-vendor-intelligence
npm install --legacy-peer-deps

cp .env.example .env.local
# Edit .env.local — set MONGODB_URI, ANTHROPIC_API_KEY, OPENAI_API_KEY
# (OPENAI_API_KEY is only needed for the posters page; the rest of the app
# degrades gracefully if it's missing.)

npm run dev
```

Open `http://localhost:3000` for the student app and `http://localhost:3000/manager` for the vendor console.

To populate the dashboard with realistic dummy data on first run:

```bash
npx tsx scripts/seed-dummy-data.ts --clean
```

## Status

This is a course final project, not a live product. The cost-per-serving numbers, campus event calendar, and exchange-week roster are placeholders in `src/data/manager/`. The demand forecast is a three-input heuristic (survey signal × campus events × exchange weeks), not a learned time-series model — anything more sophisticated would be a lie with one week of data.

If you're at SOM Dining and would like to discuss a real pilot, please open an issue or reach out.
