# YoSOM Manager — Standard Operating Procedure

**Audience:** venue managers at Yale SOM dining (Charley's Place, McNay Cafe), and the YoSOM team during demo / pilot.
**Last updated:** May 2026

---

## 1. What this app is for

YoSOM Manager turns student input from the YoSOM chatbot into actionable operating decisions for vendors. It answers four questions in under 5 minutes a day:

1. **What do students actually want next week?** (votes, free-text, themes)
2. **How many servings should I prep?** (3-input demand forecast)
3. **What should I add, keep, or drop from the menu?** (AI ops brief)
4. **How do I promote next week's feature?** (auto-generated posters)

Goal: align supply with real demand → reduce waste, lift revenue, raise satisfaction.

## 3. Daily workflow (5 minutes)

A typical morning session:

| Step | Page | What to do |
|---|---|---|
| 1 | Overview (`/manager/<venue>`) | Skim the 4 KPI cards — sessions, satisfaction, predicted servings, free-text count. Note any red/down trends. |
| 2 | Demand Forecast | Look at today + next 2 days. Are events or exchange weeks moving demand? Adjust prep. |
| 3 | AI Ops Brief | Read the **headline** and the **add/keep/drop** tables. Click "Regenerate" if data has shifted significantly since the last brief. |
| 4 | Raw Data → Reactions tab | Scan the latest negative feedback for safety / quality red flags (bad bread, late line, etc.). |
| 5 | Posters (weekly, not daily) | When piloting a new dish, generate a poster for the student app & social. |

End of week: revisit the brief and decide which recommendations to actually adopt. Track outcomes against the next week's pulse.

## 4. Page-by-page guide

### 4.1 `/manager` — Venue picker
The landing page. Choose **Charley's Place** or **McNay Cafe**. You can switch at any time using the "Switch to..." link in the sidebar.

---

### 4.2 `/manager/<venue>` — Overview Dashboard
**Goal:** one screen that tells you the state of the venue right now.

**What you see:**
- **4 KPI cards** at the top:
  - *Sessions (rolling 7d)* — how many students gave input this week.
  - *Satisfaction Pulse (0-100)* — blended score from reactions + votes + engagement. Trend arrow vs. baseline (70).
  - *Predicted Servings (7d)* — forecast total vs. baseline.
  - *Free-text Quotes* — number of students who typed an open-ended response (proxy for "felt heard").
- **Demand forecast chart** (next 7 days) with confidence band.
- **Active drivers panel** — events + exchange weeks moving the forecast.
- **Top voted items chart** + **Dietary signal donut** — what's resonating.
- **Flavors / Proteins / Cuisines** bar charts — preference trends to inform menu design.
- **Word cloud + top quotes** — voice of student.

The page **auto-refreshes every 10 seconds** so you can leave it on a TV/monitor in the kitchen.

---

### 4.3 `/manager/<venue>/forecast` — Demand Forecast
**Goal:** know how many servings to prep day by day, and why.

**The 3-input model:**

> **Predicted servings = Baseline × Survey signal × Event modifier × Exchange modifier**

| Input | Source | Effect range |
|---|---|---|
| Survey signal | Votes & preferences from student input | typically ±15% |
| Event modifier | Campus events calendar (free-lunch days, ceremonies, networking) | -45% to +20% |
| Exchange modifier | Roster of students on exchange / IXP / study trips | -1% to -15% |

**Day-by-day breakdown table** shows each multiplier per day, the prediction, the high/low band, and a confidence label (high / medium / low based on input volume).

**Use it to:**
- Cut prep for low-traffic days (e.g., Class Day catered lunch → 55% of normal).
- Up-staff for boosted days (Marketing Club coffee chat → +20% on McNay coffee).
- Spot the *driver* behind a deviation, not just the number.

---

### 4.4 `/manager/<venue>/brief` — AI Ops Brief
**Goal:** turn the noise into 3 decisions.

**Generated by Claude Sonnet 4.6.** Click "↻ Regenerate" anytime to refresh against the latest data. Briefs are cached for 5 minutes between regenerates.

**Sections:**

| Section | What it gives you |
|---|---|
| Voice-of-student headline | One sentence capturing the dominant feeling this week. |
| ✅ Add | Up to 3 candidate menu items with rationale, est. demand, dietary tags, and unit economics. |
| 🔥 Keep | High-satisfaction items to preserve. |
| ⚠ Consider dropping | Low-demand items + estimated weekly waste savings. |
| Demand forecast summary | Plain-English version of the forecast page. |
| 💰 Net budget impact | Three numbers: weekly Δ-cost, Δ-revenue, **net $ impact**. |
| 🥗 Dietary & safety flags | Coverage gaps and any allergen concerns from raw inputs. |
| 💬 Top quotes + ⚡ unusual signals | Verbatim student voices and outliers worth a manager's attention. |

**Tip:** before adopting any "add" recommendation, cross-check it against the cost table (`src/data/manager/menu-costs.ts`) and your real procurement pricing.

---

### 4.5 `/manager/<venue>/data` — Raw Data
**Goal:** the receipts. When you want to see exactly what students said.

Five tabs:
- **Preferences** — every preference card submitted (flavors / proteins / cuisines / dietary / free text).
- **Votes** — every vote with direction (▲ +1 / ▼ -1).
- **Reactions** — 👍 / 😐 / 👎 plus typed feedback.
- **Deep talk** — full chat transcripts with extracted tags.
- **Sessions** — session log (start time, source, duration, completion stage).

Use it to:
- Audit a brief's claim ("the AI says 12 students requested ramen — let me see them").
- Investigate a complaint ("which session left this negative feedback?").
- Export samples for your written report.

---

### 4.6 `/manager/<venue>/posters` — Promo Posters
**Goal:** generate a print/social-ready poster for a featured menu item in 30 seconds.

**Inputs:**
- **Featured item** — pick from candidates (recommended adds) or the current menu.
- **Vibe** — playful / bold editorial / minimalist Scandi / retro diner / tropical sunset / moody noir / confetti party / zine collage.
- **Aspect** — Portrait (Insta story), Square (Insta post), Landscape (banner).
- **Model** — DALL-E 3 (default, $0.12/poster HD portrait) or gpt-image-1 (better text rendering, $0.25/poster, requires verified OpenAI org).
- **Custom prompt** — optional; overrides the auto-composed prompt entirely.

Each generation calls OpenAI's image API. Results are downloadable PNGs.

## 6. Limits & known caveats

- **All cost numbers are placeholders.** The cost-per-serving and baseline daily-servings figures live in [`src/data/manager/menu-costs.ts`](../src/data/manager/menu-costs.ts) and are illustrative. Replace with real SOM dining data once available.
- **Events and exchange weeks are placeholders too.** See [`src/data/manager/events.ts`](../src/data/manager/events.ts) and [`src/data/manager/exchange-weeks.ts`](../src/data/manager/exchange-weeks.ts).
- **The forecast uses one week of data.** It's an aggregate-then-project model, not a true time-series forecast. Reliability improves as more weeks accumulate.
- **The brief is cached for 5 minutes** in server memory. A server restart wipes the cache.
- **Reaction filtering** in the Raw Data tab uses a substring match on `itemId` (Yuan's chatbot doesn't store venue on `Reaction` rows). Real production reactions may not filter perfectly per venue until the schema is updated.

## 7. When something looks wrong

| Symptom | Likely cause | Fix |
|---|---|---|
| All pages show 0 sessions / empty charts | Mongo connection broken or seed not run | Check `MONGODB_URI` in `.env.local`. Run `npx tsx scripts/seed-dummy-data.ts --clean`. |
| Brief never appears, spinner forever | Anthropic key missing or invalid | Verify `ANTHROPIC_API_KEY` in `.env.local`. Check console for 401. |
| Posters page errors on Generate | OpenAI key missing, billing not set up, or org not verified (gpt-image-1) | Add `OPENAI_API_KEY`, set a billing limit at platform.openai.com. Switch model to DALL-E 3 if gpt-image-1 fails. |
| Build fails on `cookies-next` peer dep | Next 15 mismatch | Already pinned via `.npmrc`. Run `npm install --legacy-peer-deps` if needed. |
| Live data not refreshing | Browser cached page | Hard refresh (Cmd+Shift+R). Overview auto-reloads every 10s. |
